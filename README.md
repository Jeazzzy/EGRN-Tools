# K Tools

**K Tools** — настольное Windows-приложение для пакетной обработки кадастровых
данных и выпускных материалов. Графический интерфейс построен на PySide6 и
объединяет инструменты для XML, ZIP, MIF, MapInfo TAB, MDB, PDF и XLSX.

## Возможности

### XML → CSV

- рекурсивный поиск файлов `proto_*.xml`;
- извлечение значений `Stage/URL`;
- сохранение ссылок в CSV с кодировкой UTF-8;
- статистика по обработанным файлам и найденным URL.

### Распаковка ZIP

- обработка ZIP-архивов ЕГРН из выбранной папки;
- определение кадастрового номера по первому XML в архиве;
- сохранение переименованных ZIP, XML и PDF в отдельные каталоги;
- защита от совпадения имён с помощью суффиксов `(1)`, `(2)` и далее;
- быстрое переименование отдельных ZIP и XML перетаскиванием в окно.

### Исправление MIF

- пакетная загрузка MIF-файлов через Drag & Drop;
- замена строки `CoordSys` на:

  ```text
  CoordSys NonEarth Units "m" Bounds (-1000000, -1000000) (19000000, 19000000)
  ```

- изменение исходных файлов на месте.

### Работа с MDB

Доступны пять массовых операций с базами Microsoft Access:

- полная замена MDB по выбранным индексам;
- перенос таблицы `Utilizations_KP` между MDB одинакового индекса;
- перенос выбранной таблицы из исходной MDB;
- обновление таблицы `Locations`;
- обновление поля `Объект_ЗУ` таблицы `Титульный_картаплан`.

Для этих операций необходим Microsoft Access Database Engine подходящей
разрядности.

### Разделение территориальных зон

- чтение границ населённых пунктов и территориальных зон из MapInfo TAB;
- автоматическое приведение систем координат;
- классификация объектов по доле пересечения и настраиваемым порогам;
- создание отдельных TAB-файлов по населённым пунктам;
- сохранение спорных и внешних объектов в `СОМНИТЕЛЬНЫЕ.tab` и
  `ВНЕ_НП.tab`.

По умолчанию зона относится к населённому пункту при пересечении не менее 98%,
а к внешним объектам — при пересечении менее 2%. Промежуточные случаи требуют
ручной проверки.

### Анализ XML

- анализ ZIP-архивов в структуре «населённый пункт / индекс»;
- извлечение индекса и кадастрового района из первого XML архива;
- сводная таблица по населённым пунктам;
- детализация соответствия индексов кадастровым районам;
- выделение населённых пунктов, в которых обнаружено несколько районов.

### Проверка выпуска

- поиск папок `pdf` и `xml` внутри выбранной папки выпуска;
- извлечение площади объекта и количества страниц из PDF;
- чтение выпускных XML внутри ZIP-архивов;
- отдельные режимы структуры выпуска для территориальных зон и населённых
  пунктов;
- проверка индекса, сведений об объекте, числа полигонов и точек;
- для выпуска НП — проверка папки населённого пункта, `type_boundary=4` и
  наличия `reg_numb_border`;
- проверка `delta_geopoint` и `geopoint_opred` с настраиваемой допустимой
  точностью;
- режим совместного применения планшетов `1:2000` и `1:10000`, разрешающий
  картометрическую погрешность `1` и `5` м в одном XML;
- цветовая индикация результатов и пояснения во всплывающих подсказках;
- экспорт результатов PDF и XML на отдельные листы XLSX.
- создание DOCX-оглавления на основе титульника выпуска, названий объектов
  из XML и накопительного количества страниц PDF;
- пункт меню «По отдельным PDF (без XML)»: названия объектов для оглавления
  извлекаются с первых страниц PDF;
- отдельное оглавление по общим PDF населённых пунктов: одна строка на PDF со
  всеми территориальными зонами НП;

## Системные требования

- Windows;
- Python 3.12 для запуска из исходного кода и сборки;
- Microsoft Access Database Engine — только для работы с MDB.

Операции с TAB используют GeoPandas, Pyogrio/GDAL, Shapely и PyProj. Все
Python-зависимости перечислены в `requirements.txt`.

## Запуск из исходного кода

В PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python .\K_Tools\main.py
```

Если PowerShell запрещает активацию скриптов, окружение можно не активировать:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe .\K_Tools\main.py
```

## Сборка EXE

Запустите из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт:

1. создаёт изолированное окружение `.build-venv`;
2. устанавливает закреплённые версии из `requirements-build.txt`;
3. проверяет чтение и запись MapInfo TAB в Python-окружении;
4. выполняет чистую сборку PyInstaller;
5. повторяет GIS-проверку внутри готового EXE;
6. публикует сборку и файл контрольной суммы только после успешной проверки.

Результат:

```text
dist/
├── K_Tools 7.2.5.exe
└── K_Tools 7.2.5.exe.sha256
```

Предыдущий рабочий EXE сохраняется, если сборка или самопроверка завершилась
ошибкой.

### Изменение версии

Номер версии и канал выпуска задаются в `K_Tools/version.py`:

```python
APP_VERSION = "7.2.5"
RELEASE_CHANNEL = ""
```

Это единый источник версии для заголовка и боковой панели приложения, свойства
Qt `applicationVersion`, имени EXE и файла контрольной суммы. Для следующего
выпуска достаточно изменить эти две константы и запустить `build.ps1`.

## Тесты

Тесты используют стандартный модуль `unittest`:

```powershell
$env:PYTHONPATH = ".\K_Tools"
python -m unittest discover -s tests -v
```

## Структура проекта

```text
K_Tools/
├── K_Tools/
│   ├── core/                 # обработка данных и общие компоненты
│   ├── hooks/                # runtime-hook PyInstaller для Pyogrio
│   ├── pages/                # страницы инструментов
│   ├── build_self_test.py    # GIS-самопроверка сборки
│   ├── K_Tools.spec          # конфигурация PyInstaller
│   ├── main.py               # точка входа
│   ├── theme.py              # светлая и тёмная темы
│   └── version.py            # версия приложения и имя EXE
├── tests/                    # автоматические тесты
├── build.ps1                 # воспроизводимая сборка Windows EXE
├── requirements.txt          # зависимости для разработки и запуска
└── requirements-build.txt    # закреплённые зависимости сборки
```

## Важные замечания

- Исправление MIF и операции с MDB изменяют исходные файлы. Перед массовой
  обработкой сделайте резервную копию.
- При распаковке ZIP используется первый найденный XML-файл.
- Кадастровый номер в имени файла записывается с подчёркиваниями вместо
  двоеточий.
- Папки `.venv`, `.build-venv`, `build` и `dist` не входят в репозиторий.
